# Weather Monitor Japan

日本の現在と直近過去の雨雲、最新のアメダス観測値とひまわり赤外画像を地図で確認する Web アプリです。v0.4では、保持している雨雲の時刻を連続再生できるようにしました。

## 起動

Node.js 24 LTS と npm を推奨します（Node.js 22.12 以上）。WebGL を利用できるモダンブラウザと、インターネット接続が必要です。API キーや環境変数、バックエンドは不要です。

```sh
git clone https://github.com/HatoAttack/weather-monitor-japan.git
cd weather-monitor-japan
npm ci
npm run dev
```

端末に表示された URL（通常は http://127.0.0.1:5173/ ）を開きます。

```sh
npm run build
npm run preview
```

本番用ファイルは `dist/` に出力されます。HTTPS の静的ホスティングに配置できます。ローカルファイルを直接開く `file://` では起動できません。公開先へのデプロイはこのタスクには含めていません。

## 操作

- 日本地図：ドラッグで移動、ホイールまたは ＋ / − ボタンで拡大縮小。
- キーボード：地図にフォーカスして矢印キーで移動、＋ / − キーで拡大縮小。
- 「観測値を地図に表示」でアメダス地点の表示を切替。「気温」「1時間降水量」「風」で色分けを変更。
- 「衛星画像を表示」で、昼夜を通して雲を確認できるひまわり赤外画像を切替。
- アメダス地点を選ぶと、地点名、標高、気温、1時間降水量、風向、風速を表示。
- 「降水レイヤーを表示」で雨雲の表示を切替。
- 時刻の選択欄、前後ボタン、スライダーで直近の観測時刻を切替。
- 「最新へ」で最新時刻に戻る。最新を表示中は新しい観測に追従する。過去時刻を選択中はその時刻を維持する。
- 「再生」で保持している雨雲を古い順に連続再生し、「一時停止」で止める。速度は「低速」「標準」「高速」から選ぶ。
- 再生中に時刻を手動で選ぶと停止する。降水レイヤーが非表示のとき、または保持している時刻が1つのときは再生できない。
- 「自動更新」は5分間隔。チェックを外すと停止し、「雨雲を更新」で手動取得できる。バックグラウンドのタブでは定期取得を控える。
- 時刻はすべて日本時間（JST）。大きく表示する時刻は、画像の読み込みに成功して地図に反映された時刻。選択した時刻を取得中・取得失敗の場合は、選択中の時刻を別に表示する。

## データと更新

降水実況は [気象庁「雨雲の動き」](https://www.jma.go.jp/bosai/nowc/)、地上観測値は [気象庁「アメダス」](https://www.jma.go.jp/bosai/map.html#contents=amedas)、衛星画像は[気象庁「ひまわり」](https://www.jma.go.jp/bosai/map.html?contents=himawari)、背景は [国土地理院「地理院タイル（淡色地図）」](https://maps.gsi.go.jp/development/ichiran.html) を利用します。

### ひまわり

- フルディスクのB13赤外画像から最新の観測時刻を選び、日本周辺へ重ねる。
- 10分ごとに最新時刻を確認し、更新失敗時は直前に表示できた画像を維持する。
- 初期状態では非表示。雨雲やアメダスとは独立して切り替えられる。
- 時系列再生と画像種別の切替はv0.4以降で扱う。

### アメダス

- 気象庁が通知する最新観測時刻を確認し、その時刻の全国地点データと地点情報を結合して表示する。
- 品質情報が正常で数値が存在する観測値のみを利用する。地点によって観測要素が異なるため、欠測は「欠測」と表示する。
- 地図の色は、気温、直近1時間の降水量、風速の各尺度を示す。風向は地点詳細で16方位表示する。
- 10分ごとに最新データを確認し、30分以上古い場合は警告する。バックグラウンドのタブでは定期取得を控える。
- タイマーの発火が早い場合は、前回の取得試行から10分になるまでの残り時間だけ待ち直す。手動更新後もその試行時刻を基準に次回取得を調整する（雨雲は同じ方式で5分間隔）。
- 更新失敗時は、直前に正常取得した地点と観測値を地図に維持する。「アメダスを更新」で手動再取得できる。

### 雨雲

- 気象庁の `targetTimes_N1.json` から `hrpns` の時刻を取得する。基準時刻と対象時刻が同じ実況だけを採用し、未来の時刻・予測は取り込まない。
- 通常は最新13時刻（5分刻みなら約1時間）。重複を除き、観測時刻順に並べる。閲覧中の過去時刻が範囲外になった場合は1時刻だけ追加保持する。
- 最新の取得データが15分以上古い場合は警告する。
- 正常、更新中、新規データなし、一時的な取得失敗、データ形式エラーを区別する。最終確認成功時刻も表示する。
- 時刻一覧の取得失敗では取得済みデータを保持する。新しい降水タイルは別のレイヤーで読み込み、表示範囲の読み込みが完了してから切り替える。画像取得失敗・タイムアウト時は直前のレイヤーと表示時刻を維持する。「画像を再試行」で再取得できる。
- タイムアウトは時刻一覧15秒、降水レイヤー20秒。設定は `src/app/config.ts` に集約する。
- 再生は保持している時刻を順に切り替える。各コマは降水画像の読み込み完了を待ってから次へ進み、読み込めない時刻は最大20秒で次へ送る。最新時刻では少し待ってから先頭へ戻る。バックグラウンドのタブでは再生を進めない。再生の対象は雨雲だけで、アメダスと衛星画像は最新時刻のみを表示する。
- 雨雲の表示切替は降水画像自身の読み込み完了で判定する。背景地図やアメダスの読み込み、地図操作が続いていても、取得済みの雨雲を表示できる。

2026-09-09 の検証では、気象庁のアメダス最新時刻・全国地点情報・全国観測値が取得でき、いずれもブラウザからの直接利用に必要な CORS 応答を確認しました。気象庁ホームページ用の配信 URL を利用しており、一般向けの安定 API として保証されているものではありません。URL・レスポンス形式・CORS の変更やデータ公開期間の終了で取得できなくなる場合があります。その場合はアダプターを確認してください。

出典と利用条件：
- [気象庁ホームページについて](https://www.jma.go.jp/jma/kishou/info/coment.html)
- [地理院タイル仕様](https://maps.gsi.go.jp/development/siyou.html)

## 構成

React + TypeScript + Vite + MapLibre GL JS。状態管理は React 標準機能のみです。

```text
src/app/                    画面構成、スタイル、設定
src/components/             地図、降水レイヤー、時刻切替、更新状態
src/hooks/                  自動更新、時間軸の再生、画面状態の接続
src/weather/domain/         アプリ内部の型とエラー
src/weather/adapters/jma/    気象庁 URL・形式の検証と変換
src/weather/services/        時系列保持・選択・更新状態
src/utils/                  日本時間の表示
e2e/                        ブラウザ統合テスト
```

元の設計資料は `AGENTS.md`、`docs/REQUIREMENTS.md`、`docs/ARCHITECTURE.md`、`docs/ROADMAP.md`、`CODEX_TASK_v0.1.md` を参照してください。

## 検証

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

本番ビルドでアメダスの描画を確認する場合は、`npm run build` の後に `npm run test:e2e -- --config playwright.production.config.ts` を実行します。専用ポート5175でWorkerのHTTP 200、観測地点の丸の描画・クリック・表示切替を検証します。MapLibreのWorkerは `src/main.tsx` でViteのWorkerアセットとして登録し、本番ファイルにも含めます。

`npm run test:e2e` は開発サーバーをポート5173で起動しますが、別の作業ディレクトリで同じポートの開発サーバーが動いていると、Playwright はそちらへ接続して古い画面を検証します。実行前にポート5173の使用状況を確認してください。

通常のブラウザテストは固定の時刻一覧と画像で実行し、外部サービスへアクセスしません。実データの検証は明示的に有効にします。

```sh
# macOS / Linux
LIVE_WEATHER=1 npm run test:e2e

# PowerShell
$env:LIVE_WEATHER = '1'
npm run test:e2e
```

既存 Chrome を使用する場合は `PLAYWRIGHT_CHROME_PATH` に実行ファイルの絶対パスを設定できます。ブラウザテストは画面操作、通信障害と復旧、画像・時刻の保持、狭い画面を確認します。実行結果は `docs/VALIDATION_v0.2.md` と `docs/VALIDATION_v0.4.md` を参照してください。

## 既知の制約と次の最小タスク

2時間の実時間・実データ検証は、PowerShellで次のように実行します（通常のテストではスキップ）。

```powershell
$env:PLAYWRIGHT_CHROME_PATH = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
$env:WEATHER_SOAK = '1'
npm run test:e2e -- e2e/stability.spec.ts --output validation-results/soak
```

20〜32分目にテスト用ブラウザだけをオフラインにし、直前の表示保持と45分目までの自動復旧を確認します。毎分のデータ時刻・取得回数・タブ表示状態・メイン描画スレッドのJSヒープ・DOM数を `validation-results/soak/` 配下の `samples.jsonl` に、進行状況と最終結果を `summary.json` に、取得要求・応答・通信失敗を `network.jsonl` に保存します。前回の記録を残す場合は実行ごとに別の `--output` を指定してください。Worker・GPU・ブラウザ全体のメモリは計測対象外です。実行中はPCをスリープさせず、同じサーバー・出力先を使うテストやアプリ・Vite設定の変更を行わないでください。この連続試験ではタブ切替を行いません。

実際のChromeタブ切替による更新停止・再開は、別の短時間テストで確認できます。

```powershell
# 通常は先に npm run build を実行。連続検証中は既存のビルドを使う。
$env:PLAYWRIGHT_CHROME_PATH = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
$env:REAL_TAB_VISIBILITY = '1'
npm run test:e2e -- --config playwright.visibility.config.ts
```

ポート5174のプレビュー、専用Chromeプロファイル、`validation-results/visibility/` を使い、連続検証と分離します。気象データは固定データで、11分の経過だけを仮想時計で進めます。`document.hidden` や `visibilitychange` は書き換えず、実際のタブ切替で非表示中の取得抑制、復帰時の両データ更新、連続した切替での重複取得防止を確認します。Chromeは画面外で起動し、終了時に閉じます。

- データと画像の保持は開いているページのメモリ内のみ。再読み込みやブラウザ終了をまたぐ保存は行わない。
- 通信が切れた状態で、未取得の地域へ移動したり未取得の倍率へ拡大したりすると、その範囲の画像は表示できない。配信終了した過去時刻についても、未取得のタイルは復元できない。
- タイルの欠損・404も取得失敗として扱い、雨がないこととは同一視しない。
- アメダスと衛星画像は最新時刻のみを表示し、過去時刻の切替と連続再生は行わない。
- 初回の JavaScript は地図ライブラリを含み約1.2 MB（gzip 約330 KB）。ビルド時にサイズ警告が出るが、ビルドは成功する。
- 2026-09-09、このPCのChromeで2時間の表示・自動更新・通信断からの復旧を確認済み。メイン描画スレッドのJSヒープは18.18〜22.13 MBで増加し続ける傾向は見られなかった。Worker・GPU・プロセス全体のメモリ、OSスリープ復帰、実機スマートフォンは未確認。
- 並行検証用ChromeのロックファイルによりViteの監視処理が終了する問題を確認したため、検証成果物を監視対象から除外。修正後の短時間再検証は成功。開発サーバー自体の2時間連続稼働は未確認（詳細は `docs/VALIDATION_v0.2.md`）。
- 再生できるのは取得済みの13時刻のみで、まだ取得していない時刻は再生中に取得しない。
- 次の最小タスクは、v0.5降水予測で取り込む対象データと完了条件を仕様にまとめること。

降水予測、警報、雷・台風などは実装していません。
