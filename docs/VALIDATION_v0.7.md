# v0.7 UI刷新（Apple Human Interface Guidelines）

## 見直し前の状態

v0.6の画面をHIGと照らし合わせ、次の問題を確認した（デスクトップ1440×900、狭い画面375×812）。

| HIGの観点 | 見直し前 |
| --- | --- |
| コンテンツを主役にする | 高さ88pxの濃紺ヘッダーが常に地図を押し下げる。狭い画面では地図が画面の約半分以下。 |
| 操作対象は44pt以上 | 地図の＋/−が29px、カードの「閉じる」が32px、再生・速度ボタンが38px。 |
| テキストスタイル | 文字の大きさが11〜24pxの間で9種類。指定していた Noto Sans JP は読み込んでいなかった。 |
| 標準的な操作部品 | 択一が押し込み式ボタン、ON/OFFがチェックボックス、矢印・再生・開閉が文字記号。 |
| 色と外観 | 独自の配色で、ダークモードに対応していない。 |
| 奥行きと素材 | パネルはほぼ不透明の白。「透明度を下げる」「コントラストを上げる」に追従しない。 |
| 情報の階層 | 時刻切替が「雨雲」セクションの奥にあり、パネルのスクロールが必須。更新状態の表示が重複。 |

進め方は `docs/ROADMAP.md` のv0.7の3段階とした。外観はOSに追従、狭い画面はボトムシート、時間軸は地図下端の再生バーとすることを決めた。

## 段階1：土台

### 実装範囲

- 設計値を `src/app/tokens.css` にまとめた。色（HIGの動的システムカラーに対応）、テキストスタイル、余白、角丸、半透明素材、影、操作対象の最小サイズ。
- `src/app/styles.css` を設計値だけを参照する形に書き直した。マークアップは変えていない。
- 外観はOSのライト/ダーク設定に従う。`index.html` に `color-scheme` とライト/ダーク別の `theme-color` を追加した。
- 地図の上に浮かぶ層（パネル、カード、地図のボタン、出典、操作の案内、地図のエラー）を同じ半透明素材で描く。
- ボタン、選択欄、セクションの見出し、チェックボックスの行、地図の＋/−を44px以上にした。
- 「透明度を下げる」「コントラストを上げる」で素材を不透明にし、「コントラストを上げる」ではボタンに輪郭を付け、副の文字と区切り線を濃くする。「視差効果を減らす」では開閉の回転をなくす。
- Windowsの強制カラーでも、状態の点・警報の色見本・色の尺度が消えないようにした。
- 使われていなかったスタイル（`.station-details`、`.display-time`）を削除した。
- 適用ルールとHIGから外している点を `docs/DESIGN.md` にまとめた。

### コントラストの確認

半透明の素材越しに地図が透けるため、素材の真下を陸・海・雨雲の各色が全面に覆った場合の合成色で、文字の設計値のコントラスト比を計算した。雨雲は実際には75%の不透明度で描くため、全面を純色で覆う条件は実際より厳しい。

| 組み合わせ | ライト（最小） | ダーク（最小） |
| --- | --- | --- |
| 本文 | 13.47 | 12.70 |
| 副の文字 | 4.79 | 5.37 |
| 警告の文字（オレンジ） | 4.86 | 6.73 |
| 予測の文字（紫） | 4.83 | 6.16 |
| ボタンの文字（青、グレーの下地） | 4.64 | 4.65 |
| リンク | 5.26 | 6.05 |
| 塗りつぶしボタンの白文字 | 4.70 | 4.70 |

最初の値（ライトの素材86%、オレンジ `#c93400`）では、最も強い雨の色（80mm/h以上）が全面に透けた場合に警告の文字が3.92まで下がった。素材を90%、オレンジを `#b83000` にして、全条件で4.5を上回るようにした。ダークの素材は、明るい地図が透けても読めるよう92%にしている。

### 画面の確認

Chrome で、ライト、ダーク、ライト＋透明度を下げる、ダーク＋コントラストを上げる、狭い画面のライト/ダークを撮影して確認した。

- ダークでMapLibreの出典表示だけが明るいまま残っていた。MapLibre側の指定（`.maplibregl-ctrl.maplibregl-ctrl-attrib`）の方が優先度が高かったため、同じ優先度で上書きするよう修正した。
- 「コントラストを上げる」で地図の＋/−に青い輪郭が付いていた。ボタン群自体に輪郭があるため、地図のボタンには付けないよう修正した。
- 観測地点のカードをライト/ダークで開き、素材、見出し、観測値の大きさを確認した。

### 検証

- lint、typecheck、単体テスト96件、production build に成功。
- ブラウザ統合テスト17件に成功（実データ・2時間連続・実タブ切替の3件は従来どおり環境変数で有効にするためスキップ）。新規6件（`e2e/appearance.spec.ts`）：
  - デスクトップ（1280px）と狭い画面（390px）で、全セクションを開いた状態の操作対象がすべて44×44px以上であること。
  - 既定ではパネルが半透明の素材で描かれること。
  - ダークモードでページの下地、パネルの文字色と素材が切り替わること。
  - 「透明度を下げる」「コントラストを上げる」でパネルが不透明になり、背景のぼかしがなくなること。
- 既存のブラウザ統合テストは、ヘッダーの高さ、地図のボタン、パネルの余白が変わっても修正なしで成功した。

### 残課題

- 折りたたんだセクションの見出しでは、データが古い・取得失敗の状態をオレンジの点だけで示している。色だけに頼らない表示は段階2・3で見直す。
- パネルは引き続きスクロールが必要。段階3（時間軸を再生バーへ移す）で短くする。
- 背景地図と気象レイヤーはダークモードでも明るい配色のまま（v0.7の対象外）。
- 実機のiPhone、iPad、Macでの表示（SF Pro とヒラギノでの見え方）は未確認。

## 段階2：配置

`claude/v0.7-ui-layout`。ヘッダーをやめて地図をウィンドウ全面にし、操作パネルをデスクトップではサイドバー、狭い画面ではボトムシートにした。気象データの取得・保持・更新のコードは触っていない。

### 変更点

- `app-header` を削除し、アプリ名と版表記（v0.7）を操作パネルの先頭へ移した。`h1` は残している。
- 地図は `100dvh` を占める。デスクトップの操作パネルは `position:absolute` で地図の左に浮かび、高さは画面に収まる範囲でスクロールする。
- 700px以下では、操作パネルを下端のボトムシートにした。既定は閉じた状態で、つまみ（grabber）だけが見える。つまみはボタンとして実装し、`aria-expanded` と `aria-controls` を付けてキーボードからも開閉できる。開くと画面の86%まで伸びる。
- 狭い画面ではこれまでパネルが地図の下に縦積みされ、地図が画面の約半分だった。ボトムシートを閉じている間は地図が全面に見える。
- 閉じたつまみで地図の出典表示と操作が隠れないよう、MapLibreの下端のコントロールをつまみの高さ（44px）だけ上げた。

### 画面の確認

Chrome（1440×900、375×812）で確認した。

- デスクトップ：ヘッダーがなくなり地図が全面。サイドバーが地図に浮かび、左右どちらにも地図が見える。
- 狭い画面：閉じた状態ではつまみのみ、地図が全面。つまみを押すとシートが開き、各セクションを操作できる。もう一度押すと閉じる。
- 出典表示は閉じたシートの上に残る。

### 検証

- lint、typecheck、単体テスト97件、production build に成功。
- ブラウザ統合テスト：新規2件（`e2e/layout.spec.ts`）を追加した。
  - デスクトップ（1280px）で `banner` ロールの要素がなく、地図がウィンドウの高さいっぱいで、サイドバーが地図に重なって浮かぶこと。`h1` が読めること。
  - 狭い画面（390px）でパネルが下端の閉じたシート（高さ80px以下）として始まり、`aria-expanded` の切替で開閉し、開いてもシートが画面を覆い切らないこと。
- 既存テストのうち2件は狭い画面の前提が変わったため修正した。`e2e/appearance.spec.ts` の44px検査と `e2e/rain-monitor.spec.ts` の狭い画面の検査は、測定・操作の前にシートを開く。
- `e2e/rain-monitor.spec.ts` の「precipitation stays visible across zoom levels」は、この変更前のコミットでも同じ環境で失敗した。今回の変更による退行ではなく、原因は下記のとおり実行時間だった。

### ズームレベル検証テストの切り分け

原因は実行時間だった。テストは7つのズームレベルで「降水レイヤーあり／なし」のスクリーンショットを比較し、各レベルで最初の比較はタイル描画前に始まるため1回やり直していた。1レベルあたり約7秒で、全体が約50秒。共通のタイムアウト（45秒）を超えていた。段階2でヘッダーがなくなり地図が縦に大きくなったぶん描画が増えて超過したが、元から余裕がなかった。

- ズーム操作のあと、降水タイルの要求が止まるまで待つ（要求数が400ms変化しなければ描画済みと見なす）ようにし、描画途中から比較を始めないようにした。
- このテストだけタイムアウトを120秒にした。ソフトウェアWebGLでのスクリーンショット比較を7回行うため、共通の45秒には収まらない。

修正後、単体でもスイート全体（19件成功、3件は環境変数で有効にするためスキップ）でも成功する。

### 残課題

- 段階3：セグメンテッドコントロールとスイッチへの置き換え、時刻切替と再生を地図下端の再生バーへ移す。
- ボトムシートは2段（閉・開）のみ。HIGの中間の段（medium detent）とドラッグでの高さ変更は入れていない。必要性を確認してから扱う。
