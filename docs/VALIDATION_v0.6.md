# v0.6 警報・注意報

## 配信の調査

### 旧配信は2026年5月末で停止

`/bosai/warning/data/warning/` 配下（`map.json` と各気象台のファイル）は、発表時刻が **2026-05-21〜05-28 で止まっている**。2026年5月29日運用開始の新しい防災気象情報（警報名への警戒レベルの付記、危険警報の新設）への移行に伴うものと考えられる。この配信を使うと、数か月前の警報を表示してしまう。

### 現行の配信

気象庁の警報ページ（`/bosai/warning/`）に埋め込まれたスクリプトから、参照先を特定した。

| ファイル | 内容 |
| --- | --- |
| `/bosai/warning/data/r8/map.json` | 全国の最新の発表。気象台×災害種別ごとに1件 |
| `/bosai/warning/data/r8/map_time.json` | 最終更新時刻 |
| `/bosai/warning/data/r8/{気象台コード}.json` | 気象台ごとの発表 |
| `/bosai/common/const/geojson/class10s.json` | 一次細分区域の境界（153地物、約289KB） |
| `/bosai/common/const/geojson/class20s/{市町村コード}.json` | 市町村の境界（1市町村＝1ファイル） |

`map.json` の各発表は `dataTypeCode` で災害種別が分かれる。区域の現在の状態は、これらの発表で「発表」「継続」となっている種別を合わせたものになる。

| dataTypeCode | 内容（観測時点で含まれていた種別） |
| --- | --- |
| VPWW55 | 大雨（03, 10） |
| VPWW56 | 土砂災害（29） |
| VPWW57 | 高潮（48） |
| VPWW58 | 暴風・強風（15） |
| VPWW59 | 波浪（16） |
| VPWW61 | その他の注意報（14, 20, 21, 24） |

気象台×種別の組は重複しないこと、警報の全142区域が境界データに含まれることを確認した。境界データにのみある `hoppo`（北方領土）は警報の対象外。いずれの配信も `Access-Control-Allow-Origin: *` を返し、ブラウザから直接取得できる。

### 種別コード

新体系のコードは、気象庁防災情報XMLフォーマットの公式コード管理表（`jmaxml_20260826_code.xlsx`、令和8年8月26日更新）の `code.WeatherWarning` で確定した。検索で見つかる「29＝特殊気象報」といった対応は別のコード表のもので、当てはまらない。

| 区分 | コード |
| --- | --- |
| 特別警報（レベル５ほか） | 32, 33, 35, 36, 37, 38, 39 |
| 危険警報（レベル４） | 43 大雨, 48 高潮, 49 土砂災害 |
| 警報（レベル３ほか） | 02〜09 |
| 注意報（レベル２ほか） | 10, 12〜27, 29 |

42, 45, 46, 47 は「未定・予約」。アプリが名称を持たないコードは推測で表示せず、パネルに「名称を持たない種別コード」として示す。

## 実装範囲（第1段階：一次細分区域）

- 一次細分区域ごとに、発表中で最も重いものを警戒レベルの色で塗る（特別警報：黒、危険警報：紫、警報：赤、注意報：黄）。
- 区域を選ぶと、発表中の種別を重い順に一覧し、発表時刻を示す。
- パネルに区分ごとの区域数、最新の発表時刻、更新状態を示す。5分ごとに確認する。
- 取得に失敗しても、直前に取得した発表状況を地図に残す。データの古さは最終確認の成功時刻で判定する（発表は数時間空くことがあるため）。
- 警報の区域は雨雲の下、背景地図の上に描く。雨雲が主役のまま、警報の範囲が分かる。
- 観測地点を選んだクリックは地点を優先し、区域の選択にしない。


## 実装

- `src/weather/domain/Warning.ts`：区分、種別、区域、全国の発表状況の型。
- `src/weather/adapters/jma/warning.ts`：公式コード表、発表の合成、境界データの取得。境界データはセッション中に1回だけ取得する。共有の取得は呼び出し元の中断に紐づけない（開発時に React が初回の取得を中断すると、共有の取得ごと失敗していたため）。
- `src/weather/services/warningMonitor.ts`、`src/hooks/useWarningMonitor.ts`：更新の確認と状態。
- `src/components/WeatherMap/WarningLayer.ts`：区域の塗りと輪郭、区域の選択。
- `src/components/WarningControls/`、`src/components/WarningCard/`：パネルと区域の詳細。

## 実装範囲（第2段階：拡大時に市町村）

警報が実際に発表される単位である市町村を、拡大したときに表示する。

- ズーム9未満は一次細分区域、9以上は市町村で塗る。ズーム9は市町村が識別できる大きさになる倍率。
- 市町村の境界は1市町村＝1ファイル（平均約2.4KB、全1,805件）で配信される。全件を読み込まず、**表示範囲にかかる区域に属し、かつ発表中の市町村だけ**を取得する。発表のない市町村は塗らないため、境界も要らない。
- 取得した境界はセッション中保持する。同時取得は6件まで。失敗したファイルは保持せず、次の表示で再取得する。
- 地図の移動が落ち着いてから（0.4秒）取得する。連続したズーム操作で途中の表示範囲を取得しないようにするため。
- 市町村は `area.json` の市町村→中間区域→一次細分区域の親子関係で区域に対応づける。全1,805市町村が区域まで辿れることを確認した。
- 市町村を選ぶと、その市町村で発表中の種別と発表時刻を表示する。

実データで確認した取得件数：中部地方をズーム9.5で表示したとき98件（約240KB）。初版では切り替え前の倍率から読み込み、途中のズーム段階ごとにも取得していたため417件だった。切り替えズームを8から9へ上げ、取得開始を切り替え後に限り、移動が落ち着くまで待つようにして減らした。

## 検証

- lint、typecheck、単体テスト96件（新規21件）、ブラウザ統合テスト11件（新規2件）、production build に成功。
- 市町村の単体テストは、市町村ごとの発表状態、中間区域を介した区域への対応づけ、境界ファイルの読み取り、ズームによる切り替え、表示範囲内で発表中の市町村だけを取得すること、古い取得結果を捨てること、移動が落ち着くまで取得しないことを確認する。
- 市町村のブラウザ統合テストは、全国表示では市町村の境界を1件も取得しないこと、拡大すると対象の1件だけを取得すること、市町村を選ぶと発表中の種別が表示されることを確認する。
- 単体テストは、発表の合成、解除の除外、重い順の並び、未知のコードの扱い、新体系コードの名称、形式変更の検出、境界データの読み取り、塗りの区分、観測地点のクリックの優先、取得失敗時の保持、古さの判定を確認する。
- ブラウザ統合テストは、区域の塗りと集計、区域の詳細、表示切替、取得失敗時の保持、復旧時の更新を確認する。
- 実データのブラウザ確認：注意報55区域が黄色で塗られ、区域を選ぶと「濃霧注意報」「レベル２土砂災害注意報」と発表時刻が表示されること。
