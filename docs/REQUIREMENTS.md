# REQUIREMENTS.md

## 1. Product goal

日本国内の現在の気象状況を、地図を中心にリアルタイムに近い形で継続表示できるWebアプリを作る。

## 2. Product concept

一般的な天気予報サイトではなく、「日本の空の現在状況を眺め続ける気象ダッシュボード」とする。

主役は地図であり、天気予報の文章やカードを主役にしない。

## 3. Target users

- 日本国内の現在の気象状況を広域で確認したい人
- 雨雲や雲の動きを継続的に見たい人
- PCやサブモニターで気象情報を常時表示したい人

## 4. Target environment

- モダンブラウザ
- デスクトップを優先
- モバイルでも閲覧可能なレスポンシブ構成

## 5. v0.1 scope

### Must

- 日本を中心とした地図を表示できる。
- ユーザーが地図をズーム、パンできる。
- 降水情報を地図上のレイヤーとして表示できる。
- 降水レイヤーをON/OFFできる。
- 現在表示している気象データの時刻を確認できる。
- 一定間隔で新しいデータの有無を確認できる。
- 過去の降水データを複数時刻保持し、時刻を切り替えて表示できる。
- データ取得に失敗してもUI全体が使用不能にならない。
- データ取得失敗時には、最後に正常取得できたデータを維持できる。

### Should

- 更新中であることを表示できる。
- 最終更新成功時刻を確認できる。
- データが古い場合に分かるようにする。
- 自動更新を一時停止できる。

### Could

- 過去データを自動再生する簡易アニメーション。
- 再生速度の変更。
- 地図の初期表示位置を保持する。

## 6. v0.1 non-goals

## 8. UI requirements

画面構成は地図を最大面積で表示する。

最低限、次の情報を常時確認できること。

- 現在表示中のデータ時刻
- 更新状態
- レイヤーON/OFF
- 時刻切り替え

情報パネルが地図を過度に隠さないこと。

## 9. Update behavior

外部データの更新頻度より細かく問い合わせ続けない。

更新間隔は設定値として管理し、外部データソースごとに変更できるようにする。

新しいデータが存在しない場合は、同一データを再登録しない。

## 10. Error behavior

次の状態を区別できること。

- 正常
- 更新中
- 新規データなし
- 一時的な取得失敗
- データが古い
- データ形式変更などによる恒常的なエラー

エラー発生時も、最後に正常取得した表示可能なデータがある場合は維持する。
